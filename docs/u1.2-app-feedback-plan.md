# Plan — U1.2: app-wide feedback channel (snackbar) for errors with no inline home

Source story: [`docs/ux-audit/ux-1-destructive-actions-and-feedback.md`](ux-audit/ux-1-destructive-actions-and-feedback.md) § U1.2 (P0).
Plan base: `feature/u1.2-error-feedback`, branched from `main` after the U1.1 merge.

## Problem

`AppViewModel` sets `_error` at eight sites — group log fetch (`AppViewModel.kt:241`),
download too large (`:361`), download failure (`:370`), pause (`:493`), unpause (`:510`),
restart (`:542`), save logs (`:575`), remove (`:595`) — and exposes it as
`val error: StateFlow<String?>` (`:126`) with `clearError()` (`:128`). **No composable
collects it.** Every failure of a detail-pane action, file download or log export is
invisible.

`ContainersScreenViewModel.error` is rendered only by the inline card on the Containers
screen (`ContainersScreen.kt:713-733`). Command-palette actions dispatch to that
ViewModel from any screen (`App.kt:245-248`), so a palette "Stop: web-1" fired from the
Dashboard fails silently. The palette also gives no acknowledgement at all on success —
the only sign anything happened is a count changing somewhere.

There is no `Snackbar`/`SnackbarHost` anywhere in the app (`grep -rn Snackbar
composeApp/src` → nothing). Settings' Danger Zone reports inline via `ActionState`,
which is fine and stays as is.

## Design decisions (decisions, not options)

- **D1.** A process-lifetime message bus, `UiMessages` (`object`, `SharedFlow<UiMessage>`),
  in `ui/state/` — the same singleton pattern as `LogsFilterState` and
  `ConsoleSessionRegistry`. `UiMessage(text, isError)`. No replay; events with no
  subscriber are dropped (a snackbar for something that happened before the host existed
  is noise).
- **D2.** One `AppSnackbarHost` composable (`ui/components/`) renders the bus with Material 3
  `SnackbarHost`. Errors: `errorContainer`/`onErrorContainer`, `SnackbarDuration.Long`;
  info: default colours, `Short`. Every snackbar has a dismiss (×) action. A new message
  **replaces** the one showing (dismiss current, then show) — it never queues behind it.
- **D3.** ViewModels are **not** edited. `App.kt` bridges:
  - `AppViewModel.error` → `UiMessages.error(it)` then `viewModel.clearError()`, always.
  - `ContainersScreenViewModel.error` → `UiMessages.error(it)` then `containersVm.clearError()`
    **only while `currentRoute != Screen.Containers.route`**. On the Containers screen the
    existing inline card remains the sole renderer (no double reporting).
  Known, accepted consequences: (i) navigating away from Containers while the inline
  card is still showing re-posts that message as a snackbar on the next screen and
  clears the card — a sequential re-announcement, never a simultaneous double, and
  never zero; (ii) an identical error string set twice within one frame (StateFlow
  conflation) is announced once.
- **D4.** Palette container actions post an **in-progress acknowledgement** at dispatch —
  `Starting <name>…`, `Stopping <name>…`, `Restarting <name>…`, and `Deleting <name>…`
  after the confirm dialog — never a success claim (the U1.3 lesson: success is not known
  at dispatch time). Failures arrive through D3. "View logs" and navigation actions post
  nothing (their effect is visible).
- **D5.** The host is mounted once, in the connected branch of `App`, as a bottom-centre
  overlay over the whole content (sidebar + detail + pane). Not in the disconnected
  branch. An error set while disconnected is dropped on reconnect (the bridge fires
  before the host's collector subscribes; the bus has no replay) — by design.
- **D6.** Out of scope: per-screen inline banners, `ErrorStateCard`, Settings `ActionState`,
  undo actions, a11y announcements (U4.1), success toasts.

### Step 1 — new `ui/state/UiMessages.kt`

Create with exactly this content:

```kotlin
package com.containerdashboard.ui.state

import kotlinx.coroutines.channels.BufferOverflow
import kotlinx.coroutines.flow.MutableSharedFlow
import kotlinx.coroutines.flow.SharedFlow
import kotlinx.coroutines.flow.asSharedFlow

/** A transient, app-wide message shown as a snackbar (UX audit U1.2). */
data class UiMessage(
    val text: String,
    val isError: Boolean,
)

/**
 * Process-lifetime bus for transient feedback that has no inline home on the
 * current screen: detail-pane actions, palette actions fired from another
 * screen, file downloads and log export. Rendered by `AppSnackbarHost`.
 *
 * Same singleton pattern as [LogsFilterState]. No replay: a message posted
 * while nothing is collecting is dropped rather than shown late. Safe to call
 * from any thread.
 */
object UiMessages {
    private val _events =
        MutableSharedFlow<UiMessage>(
            extraBufferCapacity = 16,
            onBufferOverflow = BufferOverflow.DROP_OLDEST,
        )
    val events: SharedFlow<UiMessage> = _events.asSharedFlow()

    fun info(text: String) {
        _events.tryEmit(UiMessage(text = text, isError = false))
    }

    fun error(text: String) {
        _events.tryEmit(UiMessage(text = text, isError = true))
    }
}
```

### Step 2 — new `ui/components/AppSnackbarHost.kt`

Create with exactly this content:

```kotlin
package com.containerdashboard.ui.components

import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.Snackbar
import androidx.compose.material3.SnackbarDuration
import androidx.compose.material3.SnackbarHost
import androidx.compose.material3.SnackbarHostState
import androidx.compose.material3.SnackbarVisuals
import androidx.compose.runtime.Composable
import androidx.compose.runtime.LaunchedEffect
import androidx.compose.runtime.remember
import androidx.compose.ui.Modifier
import com.containerdashboard.ui.state.UiMessages
import kotlinx.coroutines.flow.collectLatest

/**
 * Renders [UiMessages] as Material snackbars (UX audit U1.2). A new message
 * replaces the one currently showing instead of queueing behind it, so a
 * burst of failures always ends on the latest one. Errors use the error
 * container colours and stay longer.
 */
@Composable
fun AppSnackbarHost(modifier: Modifier = Modifier) {
    val hostState = remember { SnackbarHostState() }
    LaunchedEffect(hostState) {
        // collectLatest cancels the in-flight showSnackbar (which releases the
        // host's mutex and clears currentSnackbarData) before showing the next
        // message, so a burst never queues — the latest message always wins.
        UiMessages.events.collectLatest { message ->
            hostState.showSnackbar(
                UiSnackbarVisuals(
                    message = message.text,
                    isError = message.isError,
                ),
            )
        }
    }
    SnackbarHost(hostState = hostState, modifier = modifier) { data ->
        val isError = (data.visuals as? UiSnackbarVisuals)?.isError == true
        if (isError) {
            Snackbar(
                snackbarData = data,
                containerColor = MaterialTheme.colorScheme.errorContainer,
                contentColor = MaterialTheme.colorScheme.onErrorContainer,
                dismissActionContentColor = MaterialTheme.colorScheme.onErrorContainer,
            )
        } else {
            Snackbar(snackbarData = data)
        }
    }
}

private data class UiSnackbarVisuals(
    override val message: String,
    val isError: Boolean,
) : SnackbarVisuals {
    override val actionLabel: String? = null
    override val withDismissAction: Boolean = true
    override val duration: SnackbarDuration =
        if (isError) SnackbarDuration.Long else SnackbarDuration.Short
}
```

 * The app-wide feedback bus behind the snackbar host (UX audit U1.2).

class UiMessagesTest {
    @Test
    fun `info and error are delivered in order with their kind`() =
        runTest {
            val received = mutableListOf<UiMessage>()
            val collector =
                launch {
                    UiMessages.events.take(2).toList(received)
                }
            // The bus has no replay: make sure the collector is subscribed first.
            testScheduler.runCurrent()

            UiMessages.info("Stopping web-1…")
            UiMessages.error("Failed to stop web-1")
            collector.join()

            assertEquals(listOf("Stopping web-1…", "Failed to stop web-1"), received.map { it.text })
            assertFalse(received[0].isError)
            assertTrue(received[1].isError)
        }

    @Test
    fun `posting with no collector neither blocks nor throws`() {
        UiMessages.info("nobody is listening")
        UiMessages.error("still nobody")
    }
